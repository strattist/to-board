### Architecture delta and boundaries

- Layering respected: `routers/sessions.py` and `routers/room.py` call `services/sessions.py`; the unauthenticated Guest routes (`/api/room/*`) carry no `require_host`; Host routes keep it. Source: `backend/routers/*.py`.
- **A1 (low, PLAUSIBLE)** — `room_events` checks `ended_at` in a DB session, *then* registers the queue in `_connections`. An `end` request running in the threadpool can commit and call `notify_session_ended` in that gap; the stream then registers after the notification and never receives it (only keepalives). A reload or EventSource reconnect recovers. Registering the queue before the DB check closes it. Source: `backend/routers/room.py:28-40`, `notify_session_ended`. **defer**
- **A2 (accept, record)** — notification state is in-process memory (`_connections`). It holds because the container runs one uvicorn worker (`backend/Dockerfile:9`). Epic 2 retro item 5 (worker topology) is still open; adding workers would silently break Guest notification. **defer** (tie to that item).
- `room.py` and `sessions.py` are coupled one way (`sessions` imports `notify_session_ended` from `room`). Acceptable at this size; revisit if Epic 4 adds more Room events.

### Size and duplication

Every sibling Epic 3 component (`SessionDetail`, `RoomPage`, `QRReveal`) has explicit loading/error states. Source: `frontend/src/components/SessionPages.svelte`. **defer**
- **P2 (low)** — `routers/sessions.py` and `routers/room.py` use inline one-line `if …: raise …` and `;`-chained statements; `routers/games.py` uses multi-line style. Cosmetic; conflicts with "follow existing conventions" only loosely since the file predates the epic. **accept**
