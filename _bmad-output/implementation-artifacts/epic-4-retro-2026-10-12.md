### Defects found by exercising the system

- **F1 (medium, CONFIRMED)** — Session Log row titles and the Session Detail "← Session Log" back link render in the browser's default link blue (`rgb(0,0,238)`) on the dark surface: **1.79:1** for the row title on `#1e1c27` and **1.95:1** for the back link on `#15141b`. WCAG AA needs 4.5:1. The row title is the primary identifier of every history entry. Neither component sets a link `color`; `App.svelte` global CSS sets `body{color}` only, and anchors do not inherit it. The meta text (5.89:1), badges (14.3:1) and the explicit `.qr-link` (5.77:1) pass. All 48 DOM tests and the contract test pass because they assert source text and DOM structure, not rendered colour. Story 4.4's Problem statement named `muted` contrast but not link colour. Source: live Chromium run (computed styles), `SessionPages.svelte` `.row`/`.head` rules, `SessionDetail.svelte` `.page` rules, `screenshots` at 375px. **fix**
- **E1 (low)** — `parse_json` returns `[]` on any parse error, so a corrupt `players_json`/`outcomes_json` reads as "none recorded" and the next Save overwrites it silently. No path writes invalid JSON today (writes go through `json.dumps`), so this is hypothetical. Source: `backend/services/sessions.py:parse_json`. **accept**
- **E2 (low)** — `PATCH` with a non-list or non-string body still returns Pydantic's list-shaped `422` detail (live: `{"detail":[{"type":"list_type",...}]}`). The form never sends it; the UI falls back to a generic message. Already triaged as rejected in 4.2. **accept**
- **E3 (low)** — `GET /api/sessions` is unbounded and the Log fetches the full list on first load and again on each filter change. Rejected in 4.3 as out of scope for a single-Host LAN. Becomes visible only with years of history. **defer**
- **E4 (low)** — last-write-wins between two tabs editing the same Session; recorded as not patched in 4.2. **accept**
