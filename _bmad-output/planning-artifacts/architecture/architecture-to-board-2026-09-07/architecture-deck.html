Overview

to-board is a single-user, LAN-only board game night companion. The architecture reflects that: boring technology, minimal moving parts, maximum data durability. The Host (Baptiste) is the only authenticated user. Guests are anonymous readers on the same LAN.

The paradigm is a layered monolith with a compiled frontend. A single Python process (FastAPI) owns all business logic, data, and background work. The Svelte frontend compiles to static files — no server-side rendering, no Node process at runtime. nginx sits in front.

routers → services → models/workers → db   Workers call services to persist results. Nothing flows upward.

Invariants & Rules

Nine architectural decisions. These are the calls a future builder can't read off compliant code — each prevents a specific class of divergence.

AD-1
Application paradigm: Python backend + compiled Svelte frontend
BindsAll features
PreventsNode.js backend; SSR frontend; two backend languages
Backend is Python-only (FastAPI + Uvicorn). Frontend is a compiled Svelte SPA served as static files by nginx. No Node.js process runs at runtime. Monorepo: backend/ and frontend/ directories only.
AD-2
Database: SQLite, single file, SQLModel ORM
BindsFR-1, FR-2, FR-4, FR-5, FR-7, FR-9–18
PreventsTwo data stores; PostgreSQL; raw sqlite3
All structured data in a single SQLite file at /data/db/to-board.db. All access goes through SQLModel models. No second database engine is permitted.
AD-3
Persistent storage: two named TrueNAS datasets, never Docker volumes
BindsNFR-4, FR-2, FR-6, FR-15, FR-18
PreventsAny persistent file in a Docker-managed volume (lost on rebuild)
Two bind mounts, one per dataset:
  to-board-db → /data/db/ — SQLite file
  to-board-uploads → /data/uploads/ — PDFs and extracted-text cache
No volumes: key in docker-compose.yml for persistent data.
AD-4
Content stored as Markdown text in SQLite
BindsFR-5, FR-7, FR-8, FR-13
PreventsContent as separate files; HTML (XSS risk from LLM output)
CONTENT table has draft_quickstart_md, draft_cheat_sheet_md, published_quickstart_md, published_cheat_sheet_md TEXT columns. LLM instructed to return Markdown. Frontend renders to HTML client-side (sanitized). Content is human-editable via DB Browser for SQLite if a manual fix is needed.
AD-5
Pipeline state machine enforced server-side only
BindsFR-5, FR-7, FR-10, FR-14 — all Content pipeline
PreventsFrontend asserting state; double-fire of transitions; multiple published rows per game
All Content.pipeline_state transitions in backend/services/content.py. Invalid transitions → HTTP 409.

Ownership: no_rulebook → extracting is fired by the upload service before enqueuing the extraction worker. The extraction worker must NOT re-fire it.

Cardinality: UNIQUE on CONTENT.game_id — one row per game. The published_* columns survive regeneration intact until a new publish overwrites them. Guest content is always read from published_*.
AD-6
Background job model: in-process async, no separate worker
BindsFR-5, FR-6 (PDF extraction + LLM generation)
PreventsCelery / Redis; ambiguous startup recovery; extraction worker path not persisted
PDF extraction via asyncio.run_in_executor (pdfplumber is sync). LLM generation via asyncio.create_task. Both via FastAPI BackgroundTasks.

prior_pipeline_state TEXT column written on every state transition. Startup recovery reads it — no hardcoded predecessor assumptions.

Extraction worker writes RULEBOOK.extracted_text_path before transitioning state. Generation worker reads exclusively from that column — no path reconstruction from IDs.
AD-7
Real-time model: SSE for Guest session-end only; polling for pipeline state
BindsFR-14, FR-5/6 pipeline updates
PreventsWebSocket; polling for session-end; SSE for pipeline state
GET /api/room/:slug/events — one SSE connection per Guest. Server pushes event: session-ended on session close.

Pipeline state (extraction, generation) — frontend polls GET /api/games/:id at ≤5 s while pipeline_state is extracting or generating. No Host SSE stream.
AD-8
Auth boundary: Authentik OIDC on Host routes; Guest routes open
BindsAll routes; FR-12; NFR-7
PreventsLogin screen in to-board; Guest route auth; API key leaking to frontend; inconsistent encryption
Every Host route: Depends(require_host) validates OIDC JWT against Authentik JWKS (cached on startup).

Guest routes (/api/room/:slug, /api/room/:slug/events): no auth dependency. No Guest identity stored.

API key: Fernet-encrypted in SQLite. Key from env var SECRET_KEY. Implemented once in backend/core/crypto.py. Inline crypto forbidden.
AD-9
Rulebook cardinality: one active Rulebook per Game
BindsFR-2, FR-6 (upload + extraction)
PreventsGeneration worker picking wrong Rulebook row on re-upload
RULEBOOK has UNIQUE on game_id — one row per Game. On re-upload: upload service deletes old RULEBOOK row and its files (pdf_path, extracted_text_path) from /data/uploads/ in the same DB transaction before inserting the new row.

Consistency Conventions

Defaults that bind where independent builders would drift.

File namingbackend: snake_case.py — frontend: PascalCase.svelte for components, camelCase.ts for utilities
API routesREST, JSON. Host: /api/games, /api/sessions, /api/settings. Guest: /api/room/:slug, /api/room/:slug/events. Verbs via HTTP method only.
Domain nounsUse PRD §4 Glossary terms verbatim in code: Game, Rulebook, Content, PipelineState, Session, Room. Never "project", "document", "user".
IDsUUID v4 for Game.id and Session.id. Room slug: <game-slug>-<4-char-base36> (e.g. wingspan-3f2a).
room_slug_prefixURL-safe slugification of Game.title — written at game INSERT, immutable. Session-creation appends -<4-char-base36>. Single implementation: backend/core/utils.py:slugify().
TimestampsISO 8601 UTC strings in API responses. SQLite stores as TEXT. Columns: created_at, started_at, ended_at, generated_at, published_at.
Error shape{"detail": "..."} — FastAPI default. HTTP 409 for invalid pipeline transitions; 422 for validation; 404 for missing resources.
State mutationOnly backend/services/ mutates pipeline_state. Routers call services; workers call services to write results. No direct DB writes from routers or workers.
ConfigAll runtime config via environment variables. backend/core/config.py is the single config object. No hardcoded paths.
CryptoFernet only. backend/core/crypto.py is the single implementation. Inline crypto forbidden everywhere else.
No Guest dataNo logging middleware recording request IPs. No analytics. Guest SSE connections tracked in-memory only (asyncio Queue, no client IP). No Guest data in SQLite.
Markdown renderingSingle shared <Markdown> Svelte component for all content rendering. Sanitization applied before render.

Deferred

Decisions intentionally pushed down — each with the reason it can wait.

HTTPS / TLS termination — PRD A-11 defers this. Stack listens on HTTP port 80. Reverse-proxy TLS is a host-level concern outside the Compose file.
LLM provider selection UI — FR-9 allows configurable provider; dropdown vs. env-var-only mechanism is an implementation detail for the Settings epic.
Cover image storage path & serving — /data/uploads/covers/ is the natural location; whether nginx serves it directly or the API proxies it is deferred to the Game Collection epic.
pdfjs-dist worker bundling — version 6.3.289 specified; exact Vite plugin config for copying the PDF.js worker is deferred to the PDF Viewer epic.
Markdown sanitization library — <Markdown> component must sanitize LLM output; specific library (DOMPurify, marked built-in) deferred to Content Review epic.
LLM prompt versioning — prompt content, token limits, and model selection (Claude Haiku vs. Gemini Flash) deferred to the Generation epic.
Play Mode (v1.1) — deferred per UX spine; no Play Mode surfaces in v1.
v1.1 features — content quality voting, Cheat Sheet deep-links, private phone view, session photos — all deferred per PRD §7.1.
